## 1. 圆角

**原则**（官方《圆角参数》）：

1. **同层统一** —— 同一功能层级、同一类型的控件或容器，采用一致的圆角半径
2. **层级正相关** —— **层级越高，圆角半径越大**（半模态/弹出框 > 图片/标签/角标）

**通用圆角尺寸**（官方原表）：

| 数值 | 官方名称 | 官方适用场景 |
|---|---|---|
| **4vp** | 系统通用**超小**圆角 | 标签、角标、小型状态标识、迷你图标背景、细小型控件 |
| **8vp** | 系统通用**小**圆角 | 各类图片、图标、小尺寸容器、列表内模块、基础功能控件 |
| **16vp** | 系统通用圆角 | 通知卡片、普通卡片、内容容器、中型功能面板 |
| **20vp** | 系统通用**大**圆角 | 按钮、菜单、选项卡、功能入口、常用交互控件 |
| **32vp** | 系统通用**超大**圆角 | 半模态弹窗、大型弹出框、顶层浮层、重点展示容器 |

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/corner-radius-parameter-0000002556468705>
> 本地副本：`references/huawei-docs/design-guides/corner-radius-parameter-0000002556468705.md`

**系统圆角 Token 全量表**（官方原表，节选）：

| Token | 值 | | Token | 值 |
|---|---|---|---|---|
| `corner_radius_none` | 0 | | `corner_radius_level8` | 16 |
| `corner_radius_level1` | 2 | | `corner_radius_level9` | 18 |
| `corner_radius_level2` | 4 | | `corner_radius_level10` | 20 |
| `corner_radius_level3` | 6 | | `corner_radius_level11` | 22 |
| `corner_radius_level4` | 8 | | `corner_radius_level12` | 24 |
| `corner_radius_level5` | 10 | | `corner_radius_level13` | 26 |
| `corner_radius_level6` | 12 | | `corner_radius_level16` | 32 |
| `corner_radius_level7` | 14 | | `corner_radius_level18` | 36 |

**推论（本技能包的实践约定，非官方数值）**：

| 元素 | 建议圆角 | 依据 |
|---|---|---|
| 标签 / 角标 | 4 | 官方 4vp |
| 封面图 / 图标 | 8 | 官方 8vp |
| 卡片 / 分组容器 | 16 | 官方 16vp |
| 按钮 / 菜单 / 搜索框 | 20 | 官方 20vp |
| 半模态 / 抽屉 / 对话框 | 32 | 官方 32vp |
| 胶囊 / 圆形（全圆角） | `999`（或 宽度/2） | 组件形态，非 Token |

> ⚠️ 官方**未给出「抽屉」的独立圆角值**——抽屉归入「半模态」= **32vp**。
> ⚠️ **胶囊（全圆角）没有官方 Token 值**，属组件自身形态。

## 2. 间距与栅格

### 间距使用规则（官方 4 条）

1. 遵循统一栅格体系：优先使用 **4vp / 8vp 体系的倍数**，避免随意数值
2. 按层级区分：信息层级越高、独立性越强，间距越大
3. 同类元素间距一致
4. 屏幕边缘间距固定

### 屏幕边缘间隔（官方原表，泛手机）

| 位置 | 手机 | 折叠屏 | 平板 | 智慧屏 | 穿戴 | PC |
|---|---|---|---|---|---|---|
| 左右 margin | **16** | 24 | 32 | 48 | 26 | 40 |
| 顶部 margin | **36** | 36 | 36 | 27 | 20 | / |
| 底部 margin | **28** | 28 | 28 | 27 | 20 | / |

### 元素与文本间隔（官方原文数值，泛手机）

| 场景 | 值 |
|---|---|
| 卡片之间的间隔 | **12** |
| 控件间上下方向较大间隔（有明显边界） | **16** |
| 控件间上下方向普通间隔（无明显边界） | **8** |
| 控件间左右方向较大间隔 | **16** |
| 控件间左右方向普通间隔 | **8** |
| 主次文本上下间隔 | **2** |
| 主次文本左右间隔 | **8** |

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/interval-parameter-0000002562577161>

### 8vp 栅格系统（官方原文）

> 「基于 **8vp 为网格的基本单位**……一些更小的控件，例如**图标大小也可以对齐
> 4vp 的网格大小**。」

**窗口栅格档位**（官方原表）：

| 窗口宽度 | 列数 | 栅格定义（margin / gutter） |
|---|---|---|
| < 600vp | **4 Columns** | 16 / 8（通用型）或 16 / 16（宽松型） |
| 600–840vp | **8 Columns** | 24 / 12 |
| ≥ 840vp | **12 Columns** | 32 / 16 或 32 / 20 |

- 栅格**最大使用宽度 2220vp**，超出左右留白
- 单位定义：`vp` 虚拟像素；`fp` 字体像素，默认 **1 fp = 1 vp**，用户调大字体时 `1 fp = 1 vp × scale`

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/design-layout-basics-0000001795579413>

## 4. 底部页签

**两种形态**（HarmonyOS 6.1+，官方原文）：

> 「**平铺式**底部页签撑满界面底部或侧边，适配**炫彩透光模糊材质**；
> **悬浮式**底部页签悬浮在页面之上，适配**沉浸光感材质**。」

| 项目 | 平铺式 | 悬浮式 |
|---|---|---|
| **默认高度** | **48vp** | **56vp** |
| **图标默认大小** | **24 × 24** | **24 × 24** |
| 自定义运营页签 | 上下安全间距 **4vp** | 运营资源可**向上出血 4vp** |

**渐变颜色层（底部蒙层）**：建议较底部内容最顶边**高 16vp**，渐变颜色需与**页面背景色一致**。
**背板模糊分割线**：模糊背板上边缘带 **1 px** 分割线。

**页签数量**：通常 3–5 个同等重要模块；**一般选 4 个以下**；可用 **4+1**（4 功能 + 1 运营）。

**悬浮式容器宽度规则**（官方原文）：

> 底部页签由胶囊型矩形容器承载，**高度统一 56vp**。不推荐设置固定宽度。

| 条件 | 容器最大宽度 |
|---|---|
| Tabs 数量 **≥ 5** | **360vp** |
| Tabs 数量 **= 4** | **328vp** |
| 窗口 < 600 断点，3 tabs | 248vp |
| 窗口 < 600 断点，2 tabs | 168vp |
| 窗口 ≥ 600 断点，3 tabs | 272vp |
| 窗口 ≥ 600 断点，2 tabs | 184vp |

- 平板设备建议整体**放大 1.15 倍**
- **不推荐**窗口 ≥ 1440 断点时用 2–3 个底部页签（视觉体量过小）

**MiniBar（左右布局）断点建议**（官方原文）：

| 宽度区间 | 布局 |
|---|---|
| 320–440vp | **A 布局**（Tabs + MiniBar 整体居中） |
| 440–600vp；600–840 且宽高比 < 0.8 | **B 布局** |
| 600–840 且宽高比 > 0.8；840–1440vp | **C 布局** |

**上下布局**：宽度断点 320–440vp；滑动前 MiniBar 在 TabsBar 上方，
**距 TabsBar 顶部 8vp**；5 tabs 最大宽 **264vp**，4 tabs 最大宽 **296vp**。

**选中态**（官方原文）：
- 激活页签用**品牌高亮色**，或加激活动效
- 未激活页签**降低透明度或置灰**
- 切换时推荐 **`Symbol（BounceSymbolEffect-EffectDirection.DOWN）`** 点击弹跳动效
- 文本**控制在 2–4 字符**以内，英文尽量一个词
- 建议使用 **HarmonyOS Symbol**

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/bottomtab-0000001956787789>

## 5. 标题栏与工具栏

### 标题栏（官方原文）

| 项 | 值 |
|---|---|
| **单行高度** | **56vp** |
| **强调型标题栏** | **112vp** |
| 渐变模糊层高于标题栏最底边 | **32vp**（跟手隐藏情况下相同） |
| 模糊背板下边缘分割线 | **1 px** |

- 操作项过多时**用「更多」图标收进菜单**，不要全部展示
- **沉浸光感材质主要应用在可操作按钮**：左侧返回、右侧更多/搜索/文本按钮
- 渐变颜色需与页面背景色保持一致
- 电脑设备：使用**更小的字体**提高密度，且**去掉了圆形底板**
  （→ 反证手机端标题栏按钮**带圆形底板**）

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/titlebar-0000001929628982>

### 工具栏（官方原文）

| 项 | 值 |
|---|---|
| **默认高度** | **52vp** |
| 最多展示 | **4 个操作 + 1 个更多** |

**硬性约束**：
- **不允许工具栏只有「更多」**
- **不允许仅显示一个操作**
- **底部页签和工具栏不能同时使用**
- HarmonyOS 6.1 之后新增**悬浮工具栏样式**

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/toolbar-0000001929683232>

### 核心操作栏（最接近 FAB 的官方组件）

> 「核心操作栏**悬浮在页面下方**，承载核心操作和功能」→ 开发用 **HDS Action Bar**（`HdsActionBar`）
> 「**材质和投影提升页面沉浸感受**。组件背板默认带有模糊材质和投影。」

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/component_actionbar-0000002306891560>

## 6. 系统导航条与安全区

### 系统导航条（手势条）

> 官方原文：「应用在进行界面设计时，需要确保为导航条底部提供沉浸式的背景和
> **28vp 高度的抬高避让**。」

- 导航条是 HarmonyOS 的**典型特征**，是**应用必须适配**的要求
- 系统基于深浅背景为导航条提供**智能反色**
- 沉浸式场景：**默认显示，超过 2 秒不处理自动隐藏**；隐藏后从底部上滑恢复
- 游戏场景需**从底部上滑两次**手势导航才生效；其他场景一次

**必须适配的场景**：可滚动页面 / 底部固定控件 & 键盘 / 底部悬浮控件 /
半模态 & 弹出框 / 多窗 / 横屏 / 沉浸式 / 短视频。

**层级**：有弹出层时，**导航条层级比弹出层控件高**，两者避免互相遮挡。
悬浮窗内、画中画内**无需显示也无需适配**。

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/navigation-0000001957075737>

### 挖孔区（刘海）适配

> 官方 UX 标准 2.1.2.2：「界面布局需要适配摄像头的挖孔区域，若重要信息或交互操作
> （例如**底部页签/顶部页签、工具栏、标题栏、搜索框、输入框、悬浮按钮、横幅通知**等）
> 和挖孔区之间有遮挡，则需要**局部避开挖孔区**显示。」
> 「**悬浮类控件或功能（弹出框、侧边栏等）无需避开挖孔区**；可上下滚动的内容
> （列表、卡片等）无需避开挖孔区。」

**实现要点**（代码级，见 [immersive-material/safe-area.md](immersive-material/safe-area.md)）：

- 取避让区：`win.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM)` → `.topRect.height`（px）
- 全屏布局：`win.setWindowLayoutFullScreen(true)`
- 系统栏透明：`setWindowSystemBarProperties({ statusBarColor: '#00000000', navigationBarColor: '#00000000' })`
- px → vp：除以窗口 density（`getWindowDensityInfo()`）
- **必须在 `loadContent` 之前完成**，否则首帧标题栏会跳一下

## 7. 半模态与对话框

### 半模态（bindSheet）

**高度档位**（官方原文）：

| 档位 | 规则 |
|---|---|
| **Large** | 屏幕/窗口高度 − 信号栏 − **8** |
| **Medium** | **60%** 屏幕/窗口高度 |
| **Free** | 完全自定义，或按内容自适应 |

**手机（直板机）**：

| 档位 | 官方尺寸 |
|---|---|
| `Size-Regular` | 默认最大高度**距信号栏 8vp** |
| `Size-Medium` | 屏幕高度的 **60%** |
| `Size-Free` | 自定义或内容自适应 |

- 手机**横屏**：宽度最大 **480vp**，高度距屏幕顶部 **8vp** 安全间距

**平板（> 600vp 断点）**：

| 项 | 值 |
|---|---|
| 形态 | 变更为**窗口模式**，屏幕居中 |
| 默认尺寸 | **560 × 480**（高 × 宽） |
| 最小高度 | **320vp** |
| 最大高度 | 屏幕短边的 **90%** |
| Popup 容器宽度 | **400vp** |
| 尖角与指向目标间距 | **8vp** |

**电脑**：最大高度始终为**窗口高度的 90%**，跟随窗口拉伸。

**滑动优先级**（官方原文）：

| 内容位置 | 上滑 | 下滑 |
|---|---|---|
| 顶部 | 优先扩展档位（无档位则滚内容） | 优先收缩档位（无档位则关闭） |
| 中间 | 优先滚动内容 | 优先滚动内容 |
| 底部 | 呈现回弹，不切换档位 | 滚动内容直至顶部 |
| 标题栏区域 | 短滑切相邻档位；**长滑跨档至最大/直接关闭** | 同左 |

**沉浸光感相关**（官方原文）：
> 「使用半模态沉浸光感样式时，**如半模态内存在复杂的卡片容器，建议卡片容器使用
> 不透明度低于 60% 的背景色**，在保障可读性的同时增强页面沉浸感受。」
> 「如半模态内存在标题栏，建议同时使用沉浸光感样式……**关闭按钮同时需要使用
> 沉浸光感效果**。」

> ⚠️ **拖拽条尺寸、内容内边距无官方文本数值**（在官方配图中）。
> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/bindsheet-0000001956852753>

### 对话框（Dialog）

| 项 | 公式 / 值 |
|---|---|
| 宽度 | 屏幕/窗口宽度 − 两侧 Margin，**最大 400vp** 后不再响应伸缩 |
| 最大高度 | **0.9 ×（屏幕高度 − 信号栏 − 导航栏）** |
| 按钮 ≥ 3 个 | 改为**上下布局**，顺序由左至右改为**从下至上** |

- 组件**已默认提供沉浸光感样式**
- 电脑设备：弹出框自带**阴影**，分**获焦态与失焦态**

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/dialog-0000001957012569>

## 8. 按钮与点击热区

### 按钮

**重要程度**：强调按钮 > 填充按钮 > 文字按钮。
**类型**：强调 / 普通 / 文字 / **圆形按钮** / 图标按钮（带容器 / 普通）。
**尺寸**：两档 `NORMAL` / `SMALL`（`controlSize` 接口）。危险操作用**红色警告色**。

**响应式尺寸**（官方原文数值）：

| 场景 | 值 |
|---|---|
| 单个按钮横竖屏切换最大宽度 | **448vp** |
| 双按钮左右布局间距 | **12vp**，总宽与 448vp 齐平 |
| 3 个以上按钮上下排列 | 间距 **12vp** |
| 半模态内（最大宽 480vp） | 按钮两边各保留 **16vp** |
| 更大屏幕 | 保持最大 **448vp**，不再伸缩 |
| 智能穿戴 | 优先**圆形按钮**，悬浮/需明确含义时用**弧形按钮** |

**沉浸光感**（官方原文）：
> 「当按钮组件需要**悬浮在页面之上常驻**时，建议适配沉浸光感提高精致度和空间感」
> 「如需使用带有颜色的按钮样式，推荐使用沉浸光感能力的 **`materialColor`** 接口
> 进行颜色适配，**避免直接使用 `backgroundColor` 传入颜色，可能会导致沉浸光感
> 效果被覆盖**。」

> ⚠️ **圆形按钮的具体直径与图标尺寸无官方文本数值**（在官方配图中）。
> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/button-0000001929683228>

### 点击热区（唯一明确的"按钮尺寸"类硬约束）

> 官方 UX 标准 2.1.3.3：

| 设备 | 推荐 | **必须（下限）** |
|---|---|---|
| 手机 / 平板 / 折叠屏 | **48 × 48vp** | **40 × 40vp** |
| 智能穿戴 | 46 × 46vp | 40 × 40vp |
| 电脑 | 键鼠 ≥ 5mm；触屏 ≥ 7mm | — |
| 智慧屏（遥控器指向） | ≥ 4cm | ≥ 2.5cm |

**其他硬指标**：

| 项 | 要求 |
|---|---|
| 可滑动控件高度 | ≥ 屏幕高度的 **20%**（必须） |
| 长按手势接触时长 | **500 ms**（400–650 ms 可调） |
| 双击手势间隔 | **70–400 ms** |
| 图标/标题与背景对比度 | > **3:1**（推荐） |
| 正文与背景对比度 | > **4.5:1**（推荐） |
| 应用图标 | 分**前景 + 背景两层**，必须 **1024 × 1024 px**，**不允许自行裁切圆角** |

## 9. 色彩与对比度

### 系统色彩体系

基础：**宇宙蓝** + **雪域灰**。

**四个基础色 Token**（官方原文）：

| Token | 用途 |
|---|---|
| `Primary` | 最上层**文本、图标的填充与显示**；低对比度可用于二级/三级文本 |
| `onPrimary` | 显示在**强调色、图片之上**的文本、图标；**不可在常规界面使用** |
| `Brand` | **系统主题色、高亮色**；**应用可定制**，影响系统默认组件 |
| `Container` | **系统组件容器色**，用于展示组件背景填充色 |

> 「基础 Token 中的颜色会基于透明度系数分别映射出 **12 个不同的色彩参数**」
> 「系统默认颜色保障了最小 **3:1** 对比度」

**系统默认 Token 数值**（官方原表节选，ARGB，前两位为透明度）：

| Token | Light | Dark |
|---|---|---|
| `brand` | `#ff0a59f7` | `#ff317af7` |
| `warning` | `#ffe84026` | `#ffd94838` |
| `alert` | `#ffed6f21` | `#ffdb6b42` |
| `confirm` | `#ff64bb5c` | `#ff5ba854` |
| `font_primary` | `#e5000000` | `#e5ffffff` |
| `font_secondary` | `#99000000` | `#99ffffff` |

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/color-0000001776857164>

### 深浅色对比度要求（官方原表）

| 场景 | 推荐 | 一般 | 不建议 |
|---|---|---|---|
| 大字号（≥17fp 或 ≥15fp 粗体）、辅助文本、功能图标 | **> 3:1** | 1.9–3:1 | < 1.9:1 |
| 非大字号主要文本 | 浅色 **> 4.5:1**；深色 **> 5:1** | 浅色 3–4.5:1；深色 3–5:1 | < 3:1 |
| 可交互控件背板与背景 | ≥ **2.2:1** | — | — |

**色彩差异**：两个需区分的颜色，**△Euv ≥ 20**；无障碍要求下用色盲模拟器后仍需 **△Euv ≥ 20**。

**舒适性**：
- 文字**谨慎使用 > 17.6:1** 的高对比度
- 小图片、图标背板对比度建议 **≤ 15.7:1**
- 深色模式下：应用应切换深色背景，避免黑白跳转页面，**不建议大面积白色图片或背景**

**界面背景色规则**（官方原文）：
> 「**界面背景色不可为透明度颜色**」
> 「`background_primary` 一级背景色；`background_secondary` 二级背景色。
> **深色模式下，Primary 与 Secondary 对应的背景色默认都为黑色**」

> 出处：<https://developer.huawei.com/consumer/cn/doc/design-guides/dark-mode-0000001823255497>

### 自定义主题色实现

```ts
import { CustomColors, CustomTheme, ThemeControl } from '@kit.ArkUI';

export class AppColors implements CustomColors {
  public brand: ResourceColor = '#FF75D9';
  public warning: ResourceColor = $r('sys.color.ohos_id_color_warning');
}
export class AppTheme implements CustomTheme {
  public colors: AppColors = new AppColors();
}
export let gAppTheme: CustomTheme = new AppTheme();

// 页面 build 前执行
ThemeControl.setDefaultTheme(gAppTheme);
```

> 「`CustomTheme` 的属性**可选**，仅需对需要修改的 token 赋值，其余**继承系统默认**」
> ⚠️ 「**只支持应用内主题换肤，不支持 UIAbility 或窗口层面设置**，也不支持 C-API / Node-API」
> 出处：<https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/theme-skinning>

### 「简易应用」的正确表述

无底部页签、单页面 + 右上角圆形按钮的应用（如录音机），官方框架下属于
**「不使用底部页签导航的单页面 / 工具型架构」**。其应遵循：

1. **标题栏**规范（56vp 单行 / 112vp 强调型，右上角操作 + 「更多」菜单）
2. **工具栏**规范（52vp，最多 4 操作 + 1 更多；不允许只有「更多」或仅一个操作）
3. **核心操作栏**（悬浮页面下方，带模糊材质和投影）
4. **系统导航条**抬高避让 **28vp**
5. **通用 UX 体验标准**（热区、字号、对比度、系统返回）

> ⚠️ 官方**无针对此类应用的专章规范**，上述为**由现有官方章节推导的组合准则**，
> 非单一官方出处。另：官方 UX 标准 2.1.1.1 要求
> 「除一级界面外，所有全屏界面均需提供返回/关闭/取消按钮」（必须）。
